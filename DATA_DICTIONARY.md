# DATA DICTIONARY

Field definitions for the data layer. The schemas in `schemas/` are the
machine-readable version of this file.

## data/projects.csv — canonical project record

Identity and baseline commitment only. Everything later is an append-only
update.

| Field | Meaning |
|---|---|
| `project_id` | Stable slug, e.g. `measure-t-fs8`. Never change once published. |
| `project_name` | Canonical display name. |
| `alternate_names` | Pipe-separated aliases for entity resolution (`FS 8\|Fire Station No. 8`). |
| `category` | Key into `data/categories.json`: `public-safety`, `capital-projects`, `transportation`, `housing`, `parks`, `environment`, `other`. |
| `department` | City department, e.g. `San José Fire Department`. |
| `districts` | Council district number or `citywide`. Empty = not stated. |
| `measure_or_fund` | Funding measure or fund. |
| `baseline_budget_usd` | Plain number, no `$`/commas. Empty = NOT REPORTED (never zero). |
| `baseline_budget_label` | City wording when no single number exists. |
| `promised_completion` | ISO 8601 at source precision (`2024`, `2024-06`, `2024-06-30`). Year-only = estimate. |
| `promised_completion_label` | Original wording, e.g. `2024 (mid)`. |
| `baseline_source_id` | Foreign key into `data/sources.csv`. |
| `notes` | Editorial notes. |
| `review_status` | See review statuses below. |

## data/project-updates.csv — append-only update record

One row per reported position. Rows are never edited or deleted after
review; corrections add a new row.

| Field | Meaning |
|---|---|
| `update_id` | Stable unique id, e.g. `up-2026-09-29-fs8`. |
| `project_id` | Foreign key into `data/projects.csv`. |
| `reported_at` | Date of the meeting/document reporting this position (ISO 8601, day or month). |
| `reported_budget_usd` / `reported_budget_label` | As reported. Empty = NOT REPORTED. |
| `reported_completion` / `reported_completion_label` | Latest forecast or actual, at source precision. |
| `lifecycle_stage` | `planning`, `design`, `permitting`, `procurement`, `construction`, `complete`, `paused`, `cancelled`, `unknown`. |
| `status_code` | `on_track`, `watch`, `delayed`, `over_budget`, `delayed_and_over_budget`, `scope_changed`, `complete`, `paused`, `cancelled`, `insufficient_information`. |
| `change_reason` | The City's stated reason, kept separate from calculated deltas. |
| `source_id` | Foreign key into `data/sources.csv`. |
| `source_pages` | Page/section reference. Empty only when the source has no pages. |
| `review_status` | See below. |

## data/sources.csv — provenance record

| Field | Meaning |
|---|---|
| `source_id` | `sj-` + date/file slug, e.g. `sj-2026-09-29-measure-t-status-report`. |
| `document_title` | Human title. |
| `meeting_date` | ISO 8601, when the document went to a body. |
| `agenda_item` / `page_start` / `page_end` | Location within the document. |
| `source_document_url` | Live URL. |
| `archived_document_url` | Immutable copy (warning while empty). |
| `retrieved_at` | When we got it. |
| `document_sha256` | Hash of the exact file used (warning while empty). |
| `source_type` | `council_packet`, `council_report`, `committee_report`, `budget_document`, `cip_report`, `memorandum`, `minutes`, `public_notice`, `news_release`, `other`. |

## Review statuses

| Status | Meaning |
|---|---|
| `pending_review` | Migrated or extracted, awaiting Jay's first check. |
| `accepted` | Reviewed, may enter production. |
| `accepted_with_edits` | Reviewed with changes; the edit is in the row. |
| `rejected` | Not usable. Kept for the audit trail. |
| `needs_more_evidence` | Blocked from production until corroborated. |

Production builds display only `accepted` / `accepted_with_edits` records.

## Delta rules

```
budget_delta = current_budget - baseline_budget
budget_delta_percent = budget_delta / baseline_budget * 100   (baseline > 0 only)
schedule_delta = latest_completion - promised_completion      (month precision)
```

- Missing values stay null: NOT REPORTED is never zero.
- Percentages are suppressed when the baseline is zero, unknown or not
  comparable.
- Month-precision deltas are labelled as estimates; no day-level
  precision is invented.

## public-data/projects.json

Generated by `scripts/build_public_data.py` (which validates first and
refuses to build on bad data). The committed file must match a fresh build -
CI fails a PR that forgets to regenerate it.
